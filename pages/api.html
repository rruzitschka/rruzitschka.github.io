1. Authentication

Two schemes are used depending on the endpoint.

Data endpoints — X-API-Key

All /v1/climbs, /v1/training, and /v1/goals requests must include the user's API key:

X-API-Key: cnl_your_key_here

Users generate keys in the SendLog Web App under My Account → API Keys.

Key management endpoints — Firebase ID token

POST /v1/keys, GET /v1/keys, and DELETE /v1/keys/:id authenticate with the user's live Firebase session. The SendLog Web App handles this automatically — third-party apps do not call these endpoints.

Authorization: Bearer <firebase_id_token>

2. Rate Limiting

Each API key is limited to 1 000 requests per hour. The window resets on a rolling basis per key.

When the limit is exceeded:

HTTP 429 Too Many Requests
{ "error": "Rate limit exceeded (1000 req/hour)" }
↑ Back to top

3. Pagination

List endpoints that can return large result sets use cursor-based pagination.

ParameterTypeDescription
limit integer Results per page. Min 1, max 100, default 50.
after string Opaque cursor returned as nextCursor in the previous response.

Response envelope for paginated endpoints:

{
  "data": [ ... ],
  "nextCursor": "eyJpZCI6Ii4uLiJ9",
  "hasMore": true
}

When hasMore is false, nextCursor is null — you have reached the last page.

5. Key Management

These endpoints are called by the SendLog Web App when a user creates or revokes a key. They require a Firebase ID token, not an API key.

POST

/v1/keys

Firebase ID token

Create a new API key for the authenticated user.

Request body

FieldTypeRequiredDefault
label string optional "API Key"
scopes string[] optional all three scopes

Available scopes

ScopeGrants access to
climbs:readGET /v1/climbs, GET /v1/climbs/:id
training:readGET /v1/training
goals:readGET /v1/goals

Example

curl -X POST https://api-hoxktcdqvq-uc.a.run.app/v1/keys \
  -H "Authorization: Bearer <firebase_id_token>" \
  -H "Content-Type: application/json" \
  -d '{"label":"Home Dashboard","scopes":["climbs:read","training:read"]}'

Response 201 Created

{
  "id": "a3f8b2c1d4e5f6a7b8c9d0e1f2a3b4c5",
  "key": "cnl_aBcDeFgHiJkLmNoPqRsTuVwXyZ01234567890123456789",
  "label": "Home Dashboard",
  "scopes": ["climbs:read", "training:read"]
}
⚠️ The key value is returned only once. Store it immediately — it cannot be retrieved again. Subsequent list responses include metadata but never the raw key string.
GET

/v1/keys

Firebase ID token

List all API keys for the authenticated user. Raw key strings are never included.

Example

curl https://api-hoxktcdqvq-uc.a.run.app/v1/keys \
  -H "Authorization: Bearer <firebase_id_token>"

Response 200 OK

{
  "data": [
    {
      "id": "a3f8b2c1d4e5f6a7b8c9d0e1f2a3b4c5",
      "label": "Home Dashboard",
      "scopes": ["climbs:read", "training:read"],
      "createdAt": "2026-04-30T10:00:00.000Z",
      "lastUsedAt": "2026-04-30T14:23:11.000Z"
    }
  ]
}
DELETE

/v1/keys/:id

Firebase ID token

Revoke a key. Takes effect immediately — any request using the revoked key returns 401.

Example

curl -X DELETE \
  https://api-hoxktcdqvq-uc.a.run.app/v1/keys/a3f8b2c1d4e5f6a7b8c9d0e1f2a3b4c5 \
  -H "Authorization: Bearer <firebase_id_token>"

Response 204 No Content

Empty body.

6. Data Endpoints

All data endpoints authenticate with X-API-Key and return data belonging to the user who generated the key.

GET

climbs:read

List climb notes (sends and projects). Ordered by date ascending by default, or by updatedAt ascending when since is used.

7. Incremental Sync

All list endpoints support a since parameter for efficient incremental sync. Pass the updatedAt of the most recently seen record to fetch only records changed after that point. When using since, results are ordered by updatedAt ascending and the parameter is mutually exclusive with from/to.

# 1. Initial full fetch — store the max updatedAt from the response
curl "https://api-hoxktcdqvq-uc.a.run.app/v1/climbs?limit=100" \
  -H "X-API-Key: cnl_your_key_here"

# 2. On subsequent runs, pass it as `since`
curl "https://api-hoxktcdqvq-uc.a.run.app/v1/climbs?since=2026-04-30T12:00:00.000Z" \
  -H "X-API-Key: cnl_your_key_here"
💡 Remember to paginate even when using since — a large batch update could produce more than 100 changed records at once.

8. Examples

Fetch all your sends from this year (curl)

API_KEY="cnl_your_key_here"
BASE="https://api-hoxktcdqvq-uc.a.run.app"

curl "$BASE/v1/climbs?from=2026-01-01&limit=100" \
  -H "X-API-Key: $API_KEY"

Home dashboard in Python

import requests

API_KEY = "cnl_your_key_here"
BASE    = "https://api-hoxktcdqvq-uc.a.run.app"
HEADERS = {"X-API-Key": API_KEY}

# Fetch all climbs (handles pagination automatically)
climbs, cursor = [], None
while True:
    params = {"limit": 100}
    if cursor:
        params["after"] = cursor
    r = requests.get(f"{BASE}/v1/climbs", headers=HEADERS, params=params)
    r.raise_for_status()
    body = r.json()
    climbs.extend(body["data"])
    cursor = body.get("nextCursor")
    if not body.get("hasMore"):
        break

sends = [c for c in climbs if c["sendType"] != "Project"]
print(f"Total sends : {len(sends)}")
print(f"Hardest grade: {max((c['difficulty'] for c in sends), default='—')}")
